# Spec2Test AI · 技术架构与数据库设计(V1.0 基线)

> 依据:`docs/00-创业规划基线-V1.0.md` §8、§9。现有代码库为 Next.js 14 App Router + Playwright 的 MVP(JSON 文件存储),按下述方案演进。

## 1. 总体架构

```
Chrome Extension(Manifest V3, 录制/采集)      ┐
Web SaaS(Next.js on Vercel:工作台/AI 中枢)    ├→ AI 服务(OpenAI 兼容 API)
Local Runner(Node.js CLI, 用户本地执行)       ┘         ↓
                                        Supabase(PostgreSQL + Storage + Auth)
```

## 2. 现有代码库 → 目标架构的演进路径

| 现有模块 | 处置 |
|---|---|
| Next.js 14 + TS + Tailwind | 保留,新增登录与多租户 |
| JSON 文件存储(`src/lib/storage.ts`) | 第 1 步抽象 Repository 接口;第 2 步切换 Supabase 实现 |

## 3. SaaS 模块划分

```
app/
  (auth)/login, signup            — Supabase Auth(邮箱 OAuth)
  (app)/p/[projectId]/            — P1 项目工作台
  (app)/p/[projectId]/r/[reqId]/  — P2 需求分析
  (app)/t/[caseId]/code           — P3 测试代码
  (app)/runs/[runId]/             — P4 执行报告
```

## 4. 数据库设计(PostgreSQL / Supabase)

按基线 §9,需求、用例、脚本、执行**分别建实体**。

```sql
-- 租户与用户
users(id uuid pk, email, name, plan text default 'free', created_at)
workspaces(id pk, owner_id →users)
workspace_members(workspace_id, user_id, role)          -- P2 阶段启用

-- 项目
projects(id pk, workspace_id, name, target_url, created_at)

-- 需求与验收标准(追溯链起点)
requirements(id pk, project_id, title, body text, source text,   -- paste|markdown|jira
             status text default 'draft',          -- draft|analyzed|generated
             created_at)
requirement_scenarios(id pk, requirement_id, name, actor, preconditions jsonb)
acceptance_criteria(id pk, requirement_id, code text,             -- AC-001
                    given text, when_s text, then_s text,
                    category text,                                -- normal|exception|boundary
                    covered boolean default false)                -- 由用例关联自动维护

-- 测试用例与步骤
test_cases(id pk, project_id, requirement_id, code text,          -- TC-001
           title, type text, priority text,
           status text default 'ai_generated',                    -- ai_generated|reviewed|rejected
           reason text, open_questions jsonb, ac_ids uuid[],
           created_at)
test_steps(id pk, case_id, seq int, action text, selector_hint text,
           selector_verified boolean default false, input_data text,
           expected text)

-- 浏览器录制会话(插件, 41-55 天)
browser_sessions(id pk, project_id, url, recording jsonb, created_at)

-- 自动化脚本(可多版本)
playwright_tests(id pk, case_id, version int, file_name text,
                 code text, generated_at)

-- 执行
test_runs(id pk, project_id, trigger text,                        -- manual|local_runner|ci|github_pr
          runner_id text, status text, started_at, duration_ms,
          summary jsonb)                                          -- {passed,failed,skipped,coverage}
test_results(id pk, run_id, case_id, status text,                 -- passed|failed|skipped
             duration_ms, error text, expected text, actual text)
failure_analyses(id pk, result_id, failure_type text,             -- 见 PRD 六分类
                 confidence numeric, scenario text, diagnosis text,
                 suggested_next_step text, evidence jsonb)        -- 证据引用数组
artifacts(id pk, run_id, type text,                               -- screenshot|trace|log|network
          storage_path text, created_at)

-- 订阅与额度
subscriptions(id pk, user_id, plan text, current_period_end, stripe_customer_id)
ai_usage(id pk, user_id, kind text,                               -- analyze|generate|failure_analysis
         tokens int, created_at)
```

追溯查询核心 SQL 形态:
```sql
SELECT r.title, ac.code, tc.code, tc.status, tr.status AS last_run
FROM requirements r
JOIN acceptance_criteria ac ON ac.requirement_id = r.id
LEFT JOIN test_cases tc ON ac.id = ANY(tc.ac_ids)
LEFT JOIN LATERAL (
  SELECT status FROM test_results res
  WHERE res.case_id = tc.id ORDER BY id DESC LIMIT 1
) tr ON true;
```

RLS:所有表按 `workspace_id`/`owner_id` 启用行级安全(单人阶段可用 owner_id 直连)。

## 5. AI 服务层

- 统一封装:OpenAI 兼容 `chat()`,JSON 输出解析 + schema 校验 + 1 次重试;超时 60s
- 降级策略保留(规则模式),所有 AI 结果标注 `source: ai | rule`
- 每次调用写 `ai_usage`,额度中间件按套餐拦截
- A3 失败分析:提示词强制要求引用 evidenceRefs,置信度 <0.6 归 unknown

## 6. Local Runner 协议(26–40 天实现)

```
npx spec2test-runner run --project <id> --spec ./tests
  1. 从 SaaS 拉取用例/脚本清单(RUNNER_TOKEN 鉴权)
  2. 本地执行 Playwright Test --trace=on
  3. 解析 test-results:每条用例 status/截图/trace.zip/控制台
  4. POST /api/runs 上报 + 产物上传 Supabase Storage(签名 URL)
```
SaaS 内置 Runner 仅保留为 demo 模式(现有 `runner.ts`),上限额度控制。

## 7. 安全与隐私

- 用户测试代码不在 SaaS 服务器执行(demo 除外),Local Runner 优先
- 插件最小权限:仅 activeTab + 用户显式选择的元素;不上传浏览历史/Cookie/密码字段
- 产物脱敏选项:截图打码敏感输入框;提供产物删除 API
- Token(GitHub/Jira)存 Supabase Vault;发送给 AI 的内容需用户授权开关
- Supabase RLS 全表启用;Stripe webhook 验签
