# T0.3 MVP 演示脚本(5 分钟,配合访谈/预售)

> 用现有工作区 MVP 演示(http://localhost:3100,`npm run dev` 后访问)。
> 策略:演示讲"未来流程",页面讲"今天的实现";三个差异化点各配一个记忆点。

## 开场(30 秒)

"我不演示幻灯片,直接演示流程:一份需求,5 分钟内变成能跑的 Playwright 测试,而且失败时告诉你为什么挂。"

## 演示动线

### 1. 需求 → 候选用例(对应 P2,2 分钟)
- 进入「生成器」:粘贴目标 URL(用 `https://demo.playwright.dev/todomvc` 这类稳定站点)+ 一段真实需求(从受访者行业找,如支付/注册流程)
- 展示 Step 2:候选用例卡片,勾选、Regenerate
- **话术锚点(差异化 1)**:"每条用例以后都会挂到具体验收标准上——需求改了,系统知道哪些测试要重生成。你现在有这个对应关系吗?"

### 2. 用例 → 可带走的代码(对应 P3,1 分钟)
- 进入用例详情 → 「查看代码」:编辑器视图 + 行号高亮
- 点「导出 .spec.ts」下载
- **话术锚点(差异化 3)**:"代码是你的,放你自己仓库、你自己的 CI 跑。我们不锁平台——这是和 Octomind 类产品最大的区别。"

### 3. 执行 → 带证据的失败分析(对应 P4,1.5 分钟)
- 回详情页点「运行测试」(选一个故意失败的选择器演示:改一个不存在的 selector 先)
- 报告页:失败分类、错误、截图、AI 分析(原因 + 修复建议)
- **话术锚点(差异化 2)**:"Pass/Fail 没价值,价值是告诉你:这是产品 Bug 还是选择器过期了——附截图和证据。Testim 的用户在 G2 上抱怨的就是这点。"

### 4. 收尾提问(接访谈提纲第 4 节)
- 哪一步你会用?哪一步多余?
- 这个流程和你现在的比,每月省几小时?(为 LOI 铺垫)

## 演示前检查清单

- [ ] dev server 已启动(3100 端口);`npm run dev` 或 `npx next dev -p 3100`
- [ ] `.env.local` 已配置 AI Key(未配置则向导输出为规则模式,演示前说明)
- [ ] 预创建一个含失败 selector 的用例备用(网络失败时有兜底)
- [ ] 演示站点可用;准备录屏备份(网络不稳时播放)
- [ ] 全程英文界面话术(海外受访者)
